# Devops-Journey

🚀 My First Week Learning Docker: From Containers to Compose
Introduction

Last week, I started learning Docker, and it has been an amazing journey! Docker is a tool that allows developers to package applications and run them in isolated environments called containers.

Even in just one week, I’ve learned a lot, and I want to share my progress and experiences for anyone starting with Docker.

What I Learned So Far
1️⃣ Docker Images & Containers
Images are like blueprints of an application.
Containers are the running instances of those images.
I practiced creating images for Python, Node, and Java applications and running them as containers.
I also learned basic commands like docker run, docker ps, docker stop, and docker exec.
2️⃣ Docker Networking
Learned how to make two containers communicate on the same network.
Built a two-tier application where frontend and backend containers work together seamlessly.
Explored bridge networks and container linking.
3️⃣ Dockerfile Basics
Wrote Dockerfiles for my projects:
Defined base images (Python, Node, Java)
Added dependencies
Copied project files
Specified commands to run the app
Learned the importance of layer caching for faster builds.
4️⃣ Docker Volumes & Storage
Learned how to persist data using volumes.
Practiced mounting volumes to containers to ensure data is not lost when containers stop.
This is crucial for real-world applications with databases or files.
5️⃣ Docker Compose
Learned to orchestrate multiple containers easily.
Built a multi-container setup using a single docker-compose.yml file.
Now I can run complex apps with just docker-compose up.
Key Takeaways
Docker makes applications portable and consistent across environments.
Networking and volumes are essential for real-world apps.
Docker Compose saves a lot of time when running multi-container projects.
Next Steps
I want to dockerize real projects next and practice multi-container applications with databases.
Also planning to learn CI/CD integration for Docker workflows.
